# HRMS Portal — Render Deployment Guide

This guide walks you through deploying HRMS on [Render](https://render.com) using
the provided `render.yaml`. Render will provision PostgreSQL, Redis, and the web
service automatically.

## Prerequisites

- A [Render account](https://dashboard.render.com/register)
- Your code pushed to a GitHub repository
- (~$7–15/month for the Render web service + managed PostgreSQL + Redis)

---

## Step 1: Push Code to GitHub

```bash
git add .
git commit -m "Prepare for Render deployment"
git push origin main
```

---

## Step 2: Create the Render Blueprint

1. Log in to [Render Dashboard](https://dashboard.render.com)
2. Click **"New +"** → **"Blueprint"**
3. Connect your GitHub account and select the `HRMS-Portal` repository
4. Render will detect `render.yaml` and show a preview of three services:
   - `hrms-postgres` (managed PostgreSQL)
   - `hrms-redis` (managed Redis)
   - `hrms-portal` (Docker web service)
5. Click **"Apply"** to create all services

---

## Step 3: Configure the Web Service

After the blueprint applies, Render will start provisioning. Wait for
`hrms-postgres` and `hrms-redis` to become **Available**, then:

1. Click on the **hrms-portal** web service
2. Go to the **Environment** tab
3. Set `DATABASE_URL` to the PostgreSQL connection string:
   - Go to **hrms-postgres** → **Connect** tab
   - Copy the **Internal Connection String**
   - It looks like: `postgresql://hrms:xxxx@hrms-postgres-xxxx.render.com:5432/hrms`
   - **Important:** Change `postgresql://` to `postgresql+psycopg://`
   - Paste into `DATABASE_URL` in hrms-portal env vars
4. Set `REDIS_URL` from the **hrms-redis** → **Connect** tab
   - Copy the **Internal Redis URL** (e.g., `rediss://...`)
   - Paste into `REDIS_URL` in hrms-portal env vars
5. Click **Save Changes**

Render will automatically redeploy the web service with the new env vars.

---

## Step 4: Verify the Deployment

1. Click on **hrms-portal** → **Logs** to watch the build
2. Once deployed, click the service URL (e.g., `https://hrms-portal-xxxx.onrender.com`)
3. You should see the HRMS login page
4. Log in with:
   - **Employee ID:** `EMP001`
   - **Password:** `pass123`

---

## Step 5: Run the Cutover Preflight (Optional)

To verify the production database is ready:

1. In the Render dashboard, go to **hrms-portal** → **Shell**
2. Run:
   ```bash
   python scripts/cutover_preflight.py
   python scripts/check_cc_rules.py
   ```
3. Both should exit with code 0

## Environment Variables Reference

| Variable | Source | Required |
|----------|--------|----------|
| `SECRET_KEY` | Auto-generated by Render | Yes |
| `DATABASE_URL` | hrms-postgres connection string (+psycopg) | Yes |
| `REDIS_URL` | hrms-redis connection string | Yes |
| `FLASK_ENV` | `production` (set in render.yaml) | Yes |
| `APP_DB_SCHEMA` | `public` (set in render.yaml) | Yes |
| `SECRET_KEY` | Auto-generated | Yes |
| `S3_*` | Auto-generated (MinIO-compatible) | For file uploads/payslips |
| `SMTP_*` | Empty (email removed from scope) | Optional — add later for password resets |
| `ANONYMISATION_SALT` | Auto-generated | Required for user anonymisation |
| `HRMS_ALLOW_DEMO_SEED` | `0` | Prevents demo data in production |

---

## Persistent Storage

The web service has a 1 GB disk mounted at `/data`. This is used for:
- Temporary uploads
- Application data

Note: Render ephemeral disks are reset on redeploy. For production, consider
using an external object store (S3) for payslips and documents via the
`S3_ENDPOINT_URL`, `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY` env vars.

## Troubleshooting

| Issue | Solution |
|-------|----------|
| Build fails | Check **hrms-portal** → **Logs** for build errors |
| App crashes on start | Verify `DATABASE_URL` uses `postgresql+psycopg://` not `postgresql://` |
| Can't log in | Check that `SECRET_KEY` is set and `HRMS_ALLOW_DEMO_SEED=0` |
| Migrations fail | Run `alembic -c migrations/alembic.ini upgrade head` in the shell |
| 502/503 errors | Check that PostgreSQL and Redis are **Available** before the web service |

---

## Removing SMTP (Done)

SMTP/email has been removed from scope. Password resets and welcome emails are
delivered in-app only. If you later want email, add `SMTP_HOST`, `SMTP_USER`,
`SMTP_PASS`, and `EMAIL_FROM` env vars and Redeploy.
